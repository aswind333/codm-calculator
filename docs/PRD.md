# CODM 转盘概率与成本计算器 — 产品需求文档（PRD）

- **版本**：v0.3（2026-11-17；与数学规格 v0.1、UI 设计 v1.0 对齐）
- **项目代号**：codm-calculator
- **文档范围**：第一版产品功能、用户操作与验收标准；详细公式以 `PROBABILITY_SPEC.md` 为准，颜色、响应式与动画细节以 `UI_DESIGN.md` 为准。
- **目标平台**：Windows / macOS / Android / iOS 浏览器；第一版为免费托管的响应式静态网页。
- **建议技术方向**：React + TypeScript + Vite；浏览器本地计算，无需后端。

## 1. 产品目标

为《使命召唤手游》（CODM）玩家提供一个易用的转盘计算工具。玩家可先进入十抽或七抽界面，再选择具体转盘类型（7类十抽 + 1类七抽），标记已经获得的奖品，并立即查看下一抽全部剩余奖品的条件概率、当前抽奖费用、累计费用和各奖品的单轮性价比。支持自定义配置、**手动保存**、恢复默认；未来扩展模拟抽奖、多语言、离线 Android APK 与高级概率分析。

### 1.1 核心原则

1. **结果可验证**：计算基于当前奖池中未被抽走的固定初始权重，绝不把“固定抽取顺序示例”误当成实际固定概率。
2. **操作直观**：用户无需输入概率公式，只要选转盘和已抽奖品即可计算。
3. **价格透明**：区分本轮花费、此前累计花费、抽完本轮后的累计花费。
4. **可配置但不自动生效**：8种转盘分别管理价格、初始概率、奖品名称和卡片/CP单位；设置更改属于草稿，只有通过校验并点击「保存设置」后才生效；恢复默认亦同。
5. **无服务端依赖**：主要数据与计算保存在浏览器本地；不依赖游戏账号或游戏服务器。

## 2. 用户场景

- **场景 A — 查询下一抽**：用户在十抽中标记已经获得的六等奖、七等奖；系统自动识别当前是第3抽，并展示剩余8件奖品的概率与单轮等效成本。
- **场景 B — 判断是否继续**：用户选择「神话武器转盘」，已抽 5 次，查看第 6 抽的费用、各奖品中奖概率及卡片/概率性价比。
- **场景 C — 比较不同转盘**：用户在十抽/七抽界面切换类别，例如「传说载具转盘」与「神话角色转盘」，价格与累计花费同步切换；七抽界面有独立价格。
- **场景 D — 自定义活动**：用户在设置页的8行价格总表或概率卡片中修改数据、查看草稿预览，点击「保存设置」后主计算页才使用新配置；需要时可以恢复该类型默认数据，再保存。

## 3. 第一版功能需求（P0，必须实现）

### FR-01：七抽与十抽界面 + 8种转盘类型选择

- 网站提供明确的**「十抽转盘」**、**「七抽转盘」**两个入口/标签页；两者使用同一套固定权重、剔除式计算引擎。
- **十抽界面**提供以下7种可选择的转盘类型（显示名称应与价格设置页一致）：
  1. 传说载具转盘
  2. 传说近战转盘
  3. 传说载具+武器转盘
  4. 传说武器转盘
  5. 神话武器转盘
  6. 传说角色转盘
  7. 神话角色转盘
- **七抽界面**暂时只有1种类型：「七抽转盘（通用）」，不再进一步细分。以后可新增七抽类型，不应写死只能有1行。
- 每种类型包含：唯一类型ID、显示名称、奖品数量（7或10）、各奖品初始权重、各轮卡片/CP成本和单位标签。类型切换时，页面立即加载与之对应的配置。
- **用户已经抽到的奖品状态按转盘类型独立管理**，不能因为切换转盘而把其他类型的已抽状态带入当前奖池；切回原类型时可恢复该类型先前的勾选状态。
- 十抽各类型的**默认概率分布相同**，但**默认逐抽价格不同**；七抽则采用单独的7奖品概率模板及7轮价格。
- PC/Mac与手机浏览器均可使用，具体布局、标签和选择器样式留给`UI_DESIGN.md`决定。

### FR-02：点击标记已抽奖品，自动推导下一抽概率（P0）

- 用户先选择转盘类型，系统默认展示该类型**未抽取**状态（第1抽）；允许切换到之前记录的该类型状态。
- 奖品默认按「一等奖、二等奖、三等奖……十等奖 / 七等奖」命名、以稳定奖品 ID 管理。用户通过奖品卡片**点击勾选已抽取**，再次点击撤销；可按任意顺序选择多个已抽奖品。
- **不提供独立轮次输入框**：已抽数量 `k` 是唯一事实源，下一抽轮次自动等于 `k+1`（`k<N`）。这满足用户从任意已发生轮次切换/查看的需求，同时避免轮次与已抽数量不一致。界面明确显示「第几抽 / 共几抽」及「已抽几件」。
- 在每次勾选或撤销时，立即基于该类型**最后一次成功保存的有效配置**重新计算下一抽。尚未保存的设置草稿不参与计算。
- 结果表**默认完整展示所有剩余奖品**，按一等奖到末等奖排序，每行同时显示奖品等级/名称、当前下一抽真实中奖概率和单轮等效成本；**不默认折叠四等奖及以后奖品**。
- 已抽奖品在卡片网格中显示「已抽取」标志，并从剩余概率结果表中移除，不得当作仍可能中奖；其已抽状态不能只靠颜色区分。
- 提供「清空已抽记录」操作，仅清空**当前类型**的已抽集合，不影响该类型价格、初始概率以及其他类型的状态。
- 只剩一件**正权重**奖品时，该件下一抽概率是 `100.000%`；奖品全部获得后显示「转盘已全部抽完」，不再显示下一抽结果。若剩余总权重为0，显示不可计算错误而非强行写100%。
- **范围说明**：首版只计算当前集合给定时的**下一抽条件概率**；不自动枚举未来所有抽奖路径、不计算未来若干抽的累计中奖概率。

### FR-03：每件剩余奖品的本轮性价比（P0）

- 对当前下一抽仍在奖池中的**每一件奖品**计算：**「本轮每100%中奖概率等效卡片数」**。
- 若当前下一抽的成本为 `c`，目标奖品的当前条件中奖概率（0～1之间的小数）为 `p`，则 `e=c/p`（`p>0`）。数值越小表示该件奖品当前单次抽奖的单位概率成本越低。
- 示例：第1抽价格3卡、二等奖概率1.25%，则 `e=3/0.0125=240.000` 卡。
- 每行同时展示**真实条件中奖概率**与**等效卡片数**。两者都按三位小数显示；所有内部计算保留原始精度，不得拿显示用的三位小数继续运算。
- 每个结果区固定显示说明：**「等效卡片数仅用于比较本轮性价比，并非实际保底价格或期望总花费。」**
- `p=0` 时显示「当前不可抽中」，不进行除零运算；本轮价格缺失或无效时概率仍可显示，等效成本显示「待设置价格」；若成本明确为0且 `p>0`，显示 `0.000`。
- 「每1个百分点概率成本」可在未来加为辅助指标，**非首版必做**；首版只保留一种主性价比单位，避免混淆。

### FR-04：本轮、已花费和累计费用（P0）

- 费用只从当前类型的**已保存有效价格数组**读取。七抽7轮、十抽10轮；不同类型即使保底总价相同，逐轮价格也不可混用。
- 已抽 `k` 件且 `k<N` 时须同时显示：
  1. **此前已花费**：第1至第 `k` 抽成本之和；
  2. **下一抽需要**：第 `k+1` 抽成本；
  3. **完成本轮后累计**：第1至第 `k+1` 抽成本之和；
  4. **全抽总费用**：全部7/10轮成本之和。
- `k=0` 时此前已花费为0；`k=N` 时此前累计等于全抽总费用，不存在下一抽费用或完成本轮后的费用。
- 奖品的具体出奖顺序不改变相同轮次价格；修改已抽数量会即时更新累计及本轮指标。**修改设置草稿时主计算页不得提前更新，必须保存成功后才应用。**
- 价格单位显示为本类型设置的「卡/使命卡片」或「CP」等标签；首版无自动折扣、半价换算或人民币计价。
- 价格要求有限的非负整数；**0是合法的免费抽奖价格，空值不是0**。缺价或无效价涉及的合计显示「价格不完整」，概率计算本身仍不受影响。
- 「累计花费」表示**按该类型当前已保存价格配置推算的累计卡片费用**，不是逐轮真实支付流水；没有实际支付记录管理功能。

### FR-05：设置中心——价格表、初始概率、明确保存和恢复默认（P0）

#### FR-05-A：统一的8行逐抽价格大表格

- 设置页提供「**抽奖价格**」「**初始概率**」两个标签，不把所有价格和所有奖品概率堆在一屏。
- PC/Mac 的价格标签展示**8行类型 × 第1～第10抽价格列 + 合计 + 逐类重置操作**。表头与类型名称清楚，类别之间采用**统一浅灰/白/粉紫风格**，不为8行使用不同底色。
- 每个存在的轮次为可编辑输入框；七抽第8～10轮是不可编辑的「—」，不是免费的三轮；每行「合计」是草稿价格自动求和的只读字段。
- 手机端默认采用「选一种转盘 → 编辑该类型各轮费用」的表单布局；另有「查看完整价格总表」入口。PC与手机编辑同一份草稿数据，功能一致。
- 价格单位标签（如「使命卡片」「CP」）按类型配置，绝不自动做不同单位的货币转换。
- 支持「恢复该类型默认价格」「恢复全部默认价格/配置」等操作，但**都只改动未保存草稿**，不会绕过保存按钮。

#### FR-05-B：按转盘类型编辑初始概率和奖品

- 在「初始概率」标签中先选8种类型之一，下方以**7张或10张奖品小卡片网格**呈现；PC约每行5张，手机约每行2张或按空间调整。
- 每件可编辑**奖品显示名称**和以百分比录入的**初始概率**；奖品稳定ID、等级次序不因改名而改变。
- 一等奖使用皇冠、二等奖使用奖章、三等奖使用星形图标；其余奖品使用数字等级，所有转盘统一样式。
- 十抽7类初始概率预设相同，但修改和保存应**仅影响选中的具体类型**，不连带修改其他类型；七抽只有7件奖品。
- 编辑过程中实时显示「概率合计 XX.XXX%」以及具体校验错误；初始权重为有限、非负值，必须合计100%，容差与剩余权重为0等规则遵循 `PROBABILITY_SPEC.md`。
- 「恢复当前类型默认概率」仅修改该类型草稿，尚未保存时不影响正式计算结果。

#### FR-05-C：显式保存、校验、取消与本地持久化

- **必须有醒目的「保存设置」按钮。禁止自动保存或编辑后自动生效。**
- 任一价格、概率、奖品名称或单位修改后，界面显示「有未保存的修改」；在价格与概率标签、各转盘类型之间切换时保留全部草稿。
- 点击「保存设置」时校验**本次将要保存的所有类型配置**，通过后统一应用到计算页并写入浏览器本地存储；保存成功才显示「设置已保存」。
- 当初始概率和不为100%、价格为空/非整数/负数，或存在其他非法值时，显示针对性的错误，并禁用/拒绝保存；**旧的已保存有效配置继续生效**。
- 提供「取消修改」：放弃未保存草稿，恢复最近一次成功保存的配置；存在草稿变更时建议确认。
- 「恢复某类型默认」「恢复全部默认」只修改草稿；**恢复全部前必须二次确认**，且仍需点击「保存设置」才应用。
- 在站内导航离开设置页时，如果仍有未保存更改，必须弹出「继续编辑 / 放弃修改」确认；对于刷新或关闭标签页，使用浏览器允许的离开提醒，但不保证能自定义提醒文案。
- 浏览器刷新或再次打开网站后只恢复**已保存成功**的配置；未保存草稿可丢失。本地数据被用户清除、无痕模式限制、存储失败的情况要给出恰当提示；**存储失败不得宣称已保存**。
- 默认预设与用户配置分别保存，重置必须回到§4的内置常量，不能把已编辑数据当默认值。

### FR-06：规则说明页面（P0）

- 顶部有清晰可见的「规则说明」入口；规则页采用适合PC、Mac和手机阅读的**居中单列布局**，并有清楚的返回计算器按钮。
- 页面依次设置四个模块：
  1. **三步使用教程**：选择转盘 → 点击奖品标记已抽 → 查看下一抽的全部概率、单轮等效成本与花费；提示修改设置后需点击保存。
  2. **概率计算说明**：介绍固定权重、不放回剔除、归一化公式；提供可切换的十抽/七抽示例，**只影响说明案例，不改主计算页状态**。
  3. **性价比指标说明**：用「10卡 / 5% = 200.000卡」解释“每100%概率等效卡片数”，并明确它不等于保底或真实期望总花费。
  4. **FAQ折叠问答**：至少覆盖“不同已抽奖品为何导致不同概率”“性价比是否是平均花费”“显示概率和不恰好100%”“修改设置为何未生效”“最后一抽是否100%”“浏览器本地保存是否永久”等。
- **十抽示例**：已获得六等奖（6.5%）与七等奖（10%），剩余权重83.5%，第3抽二等奖 `1.25/83.5×100%=1.497%`。
- **七抽示例**：已获得七等奖（60%），剩余权重40%，第2抽二等奖 `1.25/40×100%=3.125%`。
- 说明当且仅当最后一个剩余奖品权重大于0时其概率为100%；说明概率结果显示3位小数、四舍五入可能造成显示合计偏差。
- 页面底部明确写出**非官方玩家工具**声明：实际活动规则、价格及概率以游戏内公示为准；如引用Garena公告，必须准确标注服务器，不得把台服公告冒称国服官方公告。

### FR-07：统一响应式布局与视觉反馈（P0）

- 采用**一套响应式 UI**，无需为PC与手机各维护一套计算逻辑；主视觉采用浅灰背景、白色卡片、粉紫主题及少量淡蓝辅助，直观清爽，所有类别统一配色。
- 主计算页使用**可点击奖品卡片网格而非圆形轮盘**；一至三等奖使用皇冠/奖章/星形，结果表完整列出未抽奖品。
- 顶部导航有「概率计算」「规则说明」入口，右上角设置按钮为醒目的粉紫齿轮；附近有「可自定义概率」文字与**低幅度轻微动效箭头**，且能在减少动态效果设置下停止动画。
- PC计算页可以奖品网格与结果表左右排列；手机按「转盘类型 → 当前状态/花费 → 奖品 → 完整结果」从上到下排列。手机设置价格采用逐类型编辑，支持查看完整大表格。
- 轻量过渡仅用于卡片选中、按钮反馈、说明FAQ等，不使用真实圆形转盘、随机抽奖动画、粒子爆炸或3D武器展示作为首版功能。
- 核心数据应清晰可读，状态不能只靠颜色区分，触摸/键盘可操作；具体颜色、动画幅度和断点以 `UI_DESIGN.md` 为准。

### 4.4 8行价格设置总表的结构与说明

- **8行**：上面7类十抽 + 七抽通用，名称与计算页选择器一一对应。
- **10个价格列**：十抽填满10列；七抽仅前7列可编辑，第8～10列禁用或「—」。
- **1个合计列**：根据有效轮次价格自动计算；合计字段不可直接编辑。
- **概率编辑方式**：使用设置页独立的「初始概率」标签，再从其中选择8种类型之一；不要求在价格大表格内放置概率编辑按钮。
- **恢复默认入口**：支持逐类型价格/概率重置，也支持恢复全部；操作均先作用于草稿，必须再点击「保存设置」才生效，且不影响未选择的其他类型。
- **数据模型约束**：奖品数量由预设类型决定，`prices.length`必须为7或10；不允许将7轮价格数组当作10轮来累计。类型数量可在未来扩展，但首版有且仅有上述8种内置类型。

### 4.5 两种转盘共通规则

- **固定权重、不放回剔除**：抽中过的奖品从奖池中剔除；剩余奖品初始权重不变，重新归一化。
- 下一抽某奖品概率 = `该奖品初始权重 / 当前所有剩余奖品初始权重之和 × 100%`。
- 同一剩余奖品集合，无论之前的剔除先后次序如何，下一抽概率相同。
- 所选转盘类型只决定奖品数、初始权重预设和逐轮成本，不应改变共用概率算法。
- 十抽规则已由用户在国服实测核对，七抽的初始概率与固定权重剔除规则来自用户提供的Garena公告截图。不同服或特殊活动的价格可能不同，均可在设置页修改。
- 具体精度、取整、边界条件、测试与状态表示另写入`PROBABILITY_SPEC.md`。

## 5. 首版产品约定与异常状态

1. **显示精度锁定**：中奖概率和每100%概率等效卡片数均**固定保留小数点后三位、四舍五入**；真实单轮/累计卡片数为整数。算法中保持未舍入精度，绝不以显示值做下一步运算。极小正概率显示 `0.000%` 时可附加「实际大于0，因显示精度舍入」说明，**不增加主显示小数位**。
2. **轮次由已抽集合决定**：用户点击/撤销已抽奖品，`k` 自动变化，下一抽为第 `k+1` 轮（`k<N`）；不提供独立手动选择轮次输入控件。
3. **结果完整可见**：所有剩余奖品的概率和等效成本默认展示，不折叠、不只显示前三等奖；已抽卡片明确标识。
4. **保存前后分离**：修改价格或概率时，设置页的草稿总计/合法性可以实时更新，但计算页仍使用已保存配置；只有「保存设置」成功后才刷新正式计算结果。
5. **概率数据错误**：无效概率总和不可提交；若目前剩余权重为0，显示「当前状态无法计算，请检查设置或已抽奖品」而不是强制设为100%。允许零权重奖品但其当前概率为0时，等效成本不可计算。
6. **价格数据错误**：允许价格为0，拒绝空输入、负值、非整数或非有限数；不完整费用不得显示为0或凭空累计。
7. **终局**：最后一件正权重奖品概率 `100.000%`，等效成本恰等于最后一抽卡片数；全部抽完则显示完成，无下一抽。
8. **本地隐私与限制**：无需注册、登录或同步游戏账号；已保存配置保存在当前设备浏览器本地，清除浏览器站点数据可能导致丢失。实际已抽状态应按类型独立管理，持久化方式由实施计划确定，不能未经说明上传。
9. **来源与版权**：所有初始概率与价格是项目的可编辑默认模板，不宣称适用于所有服务器和所有活动；页面不依赖未授权的游戏素材，游戏规则以实际游戏公告为准。

## 6. 后续版本需求（暂不纳入第一版验收）

### EX-01：模拟抽奖

- 在七抽和十抽中分别选择模拟模式，按照当前配置概率进行不放回随机抽取。
- 可观看抽奖动画及奖品揭晓；实际随机结果由概率引擎决定，动画仅展示结果。
- 模拟记录与用户实际已抽状态**分开管理**，避免互相污染；支持重置模拟。

### EX-02：多语言

- 支持简体中文、繁体中文（台服）、日语、英语。
- 第一版使用简体中文；将文案集中管理，以便后续国际化而非把界面文字散落在代码里。

### EX-03：离线 APK

- 维持纯前端计算与本地数据方案，以便以后用 Capacitor 包装为 Android APK。
- 核心算法不得依赖浏览器网页域名或远程接口；应用必要资源尽量本地打包。
- Android 构建、签名、更新和分发另立技术任务；首版不承诺交付 APK。

### EX-04：候选增强项（未确认）

- 预览未来所有可能已抽组合／中奖路径（需要额外状态枚举与交互设计）；
- 从当前状态出发、截止未来某轮的累计目标中奖率，以及一直抽到目标的真实期望总花费；
- 半价活动、卡片价格换算人民币、不同服务器 CP 价格模板；
- JSON 配置导入/导出与多个自定义转盘存档；
- PWA 添加到主屏幕和离线缓存。

> 上述是建议加入需求池的功能，**不是用户已经确认必须在第一版实现的范围**。需分别决定优先级并编写数学／交互规格。

## 7. 非功能需求

- **兼容性**：最新版主流 Chromium、Safari、Firefox 浏览器；优先手机触屏体验，Windows/macOS/Android/iOS 使用同一套功能。
- **响应式**：约375/430/768/1280 CSS px 断点附近进行检查；移动端整体不横向溢出，价格大表格可局部横向滚动，亦有逐类编辑入口。
- **性能**：单次勾选/撤销奖品、切换类型时立即本地计算，除首次加载静态资源外不依赖网络；7/10件奖品无需后端。
- **可维护性**：概率纯函数与 React/UI 分离，默认数据和用户已保存数据分离；统一配色主题令牌，便于将来更换风格。
- **无障碍**：按钮标签明确，状态不只靠颜色，支持键盘和基本屏幕阅读器语义；尊重 `prefers-reduced-motion`，轻动画不阻碍数据展示。
- **发布**：首版 GitHub 管理代码、免费静态站托管（拟 Cloudflare Pages）；不开发服务端、用户账号、数据库或在线实时游戏接口。
- **本地数据**：保存成功后跨刷新保留，保存失败要提示；未保存草稿不影响生效配置。
- **未来兼容**：核心计算与浏览器特定功能分离，必要图标/字体本地打包，便于未来 Capacitor 转离线 Android APK。

- **AC-05**：十抽勾选六等奖6.50%和七等奖10.00%后，自动显示**第3抽**、剩余权重83.50%；一等奖显示**`0.096%`**、二等奖**`1.497%`**；若第3抽10卡，二等奖等效成本显示**`668.000`**、一等奖**`10,437.500`**卡。

- **AC-12**：仅剩一件且权重为正时显示**`100.000%`**，本轮等效成本等于该轮价格；全部抽完显示完成，无第N+1抽。

- **AC-13**：通过奖品卡片任意勾选/取消已抽物品，系统自动从已抽数量推导第几抽；无独立轮次输入导致的矛盾状态，清空只作用于当前类型。
