# CODM 抽奖概率与成本计算器 — UI / UX 设计规范（UI_DESIGN）

- **版本**：v1.0（2026-11-17，已讨论确认的首版 UI 设计基准）
- **项目**：`codm-calculator`
- **适用平台**：Windows / macOS / Android / iOS 现代浏览器；采用响应式网页设计
- **首版语言**：简体中文
- **关联文档**：`docs/PRD.md`、`docs/PROBABILITY_SPEC.md`
- **实现方向**：React + TypeScript + Vite；优先本地资源，不依赖在线图片、字体或外部 API
- **文档定位**：规定页面结构、信息层级、视觉风格、交互状态与响应式行为；**数学公式、默认权重、价格和计算边界以 `PROBABILITY_SPEC.md` 为准**。

> **产品定位**：一款给 CODM 玩家快速查看「已抽什么、下一抽是什么概率、下一抽要多少钱、本轮每件道具的概率成本」的轻量工具。**直观和易读优先于装饰**。首版不模仿游戏内的圆形转盘，也不实施模拟抽奖。

## 1. 已确认的总体原则

1. **视觉风格**：浅灰背景、粉紫主色、少量淡蓝辅助；活力、小清新、柔和、现代。以大面积中性色保证数据可读，不做深色军事科技主题。
2. **统一设计**：所有转盘类别使用统一表格和组件风格；**不为8种转盘分别使用不同底色**，避免画面杂乱。
3. **一套响应式界面**：PC / Mac / 手机共用功能和计算引擎，根据宽度调整布局；无需维护独立的移动版页面。
4. **信息完整**：下一抽所有未抽奖品的概率与性价比**默认全部展示**，不折叠四等奖及之后的结果。
5. **轻量动效**：只使用柔和的状态切换、数字更新和提示箭头动画；禁止持续闪烁、夸张粒子和干扰读数的特效。
6. **明确保存**：设置页用户修改的数据属于**草稿**，必须点击「保存设置」才生效并持久化；**不自动保存**。恢复默认也需再次保存。
7. **规范与可复用**：颜色和尺寸集中定义为主题变量；计算、设置、规则说明共享组件。以后更换主题无需重写概率算法。
8. **非官方工具**：界面显著但克制地注明网站与 CODM 官方无隶属关系，游戏实际活动以游戏内说明为准。

## 2. 信息架构与导航

首版包含三个主要页面（可采用客户端路由或等价的页内切换，不强制具体路由库）：

| 页面 | 导航名称 | 主要用途 | 首版优先级 |
|---|---|---|---|
| A | **概率计算** | 选择转盘、标记已抽奖品、查看下一抽概率 / 等效成本 / 花费 | P0，默认首页 |
| B | **设置** | 修改8类转盘的逐抽价格、初始概率及名称 / 单位，保存或恢复默认 | P0 |
| C | **规则说明** | 使用教程、计算规则示例、性价比解释和 FAQ | P0 |

### 2.1 顶部导航

- 左上角显示**「CODM 抽奖计算器」**（可配简单原创几何标识），副标题可以是「概率 · 花费 · 性价比」。
- 顶部始终有可见的**「规则说明」按钮**，配 `book-open` 图标，点击进入规则说明页。
- **右上角「设置」按钮必须醒目**：粉紫色圆角底、白色 `settings` 齿轮图标，具有明确的可点击态。
- 在主计算页的设置按钮附近放置**「可自定义概率」**文案和指向齿轮的小箭头；箭头做轻微上下浮动/指向动效。提示文案可在展开的页面中补一句「也可修改卡片价格」。
- 手机端仍保留「规则说明」和「设置」入口，不可因宽度变窄而只留下无法辨认的隐藏导航。
- 设置或规则页须提供清晰的「返回概率计算」入口；不能仅靠浏览器后退。

### 2.2 设置提示箭头行为

- 文案：**「可自定义概率」**（用户确认用语）。
- 箭头每次仅小幅移动，例如 3–5 px，持续约 1.5–2.5 s、低频循环；不能遮盖按钮、干扰内容点击。
- 推荐用户成功进入过设置页后**减弱或停止动画**；即使不记录访问状态，默认动画也应非常克制。
- 系统开启 `prefers-reduced-motion: reduce` 时完全停止运动，保留静态文字与箭头。

## 3. 设计令牌：配色、字体、卡片与状态

### 3.1 建议初版颜色（可集中修改）

| 用途 | 建议色值 | 使用规范 |
|---|---|---|
| 页面浅灰底色 | `#F4F5F8` | 背景大面积使用 |
| 主内容卡片 | `#FFFFFF` | 主面板、表格、输入区域 |
| 粉紫主色 | `#AA93E9` | 主要按钮、选中态、重点装饰 |
| 深粉紫文字 / 强调 | `#8057C6` | 重点数字与可交互状态（需核对对比度） |
| 粉色点缀 | `#F4B8DB` | 次要装饰、奖品标签 |
| 淡蓝辅助 | `#B7DBF5` | 说明提示和辅助信息区域 |
| 深灰正文 | `#343447` | 主要文字，保证对比度 |
| 次级文字 | `#6F6A7B` | 辅助文字与说明 |
| 边框 | `#E5E0ED` | 表格分隔、卡片轮廓 |
| 危险 / 校验错误 | 建议深玫红 `#B33B65` | 错误信息必须同时有文字提示 |
| 成功 / 校验通过 | 建议深青绿 `#277969` | 保存成功、概率合法（不能只靠颜色） |

**使用约束**：粉紫与粉色不用于整屏铺底；柔和的浅色主要充当背景与装饰，输入文字和重要数据采用更深颜色。最终实现时确保正常字号文本与背景具有足够对比度，目标参照 WCAG AA（正文至少 4.5:1，较大文字至少 3:1）；如建议色值不足，Codex 应优先加深文字颜色，而非牺牲可读性。

### 3.2 排版与基础组件

- 字体优先使用清晰的系统无衬线字体 / 许可允许的本地打包字体；首版中文优先。**不依赖运行时 Google Fonts 等外部字体请求**。
- 数字使用表格等宽数字（`font-variant-numeric: tabular-nums`），减少更新时左右跳动。
- 主内容卡片建议 12–16 px 圆角，按钮 8–12 px，阴影低强度，区块之间留足空间。
- 核心操作按钮的移动端触摸区域建议不小于 44 × 44 CSS px；文字和图标具备明确提示。
- 图标优先 Lucide 或原创 SVG：一等奖 `crown`、二等奖 `medal`、三等奖 `star`，其他奖品使用普通数字编号。不强制提供枪械立绘。
- 不使用未授权的 CODM 游戏原画、武器皮肤、Logo 作为第一版必备资源；尽量避免版权和离线打包障碍。

## 4. 页面 A：概率计算（默认首页）

### 4.1 信息层级与布局顺序

由上到下的逻辑顺序：

1. 顶部导航：产品名称、**规则说明**、显眼的设置入口及「可自定义概率」箭头提示。
2. **转盘类型选择**：先区分「十抽 / 七抽」，再选择具体类别（可合并为分组下拉框，但标签要清楚）。
3. **状态与花费摘要**：当前轮次、已抽数量、此前累计花费、下一抽所需卡片；适当位置展示「完成本轮累计」及「全抽总费用」。
4. **奖品选择网格**：按一等奖至十等奖（或七等奖）排列，可点击标记和取消已抽状态。
5. **概率与性价比结果表**：默认列出**全部剩余奖品**，按等级排序；不可折叠隐藏。
6. 简短说明：等效卡片数的含义和「非保底、非真实期望花费」提示。

### 4.2 转盘选择器

- 十抽显示7类：**传说载具、传说近战、传说载具+武器、传说武器、神话武器、传说角色、神话角色**。
- 七抽目前只显示**「七抽转盘（通用）」**，后续可扩充类别。
- 默认进入「十抽」；十抽的初次默认类别建议「传说武器转盘」（只是 UI 初始选项，不更改任何默认价格或概率）。
- 每个类型独立维护已抽集合和已保存的自定义设置；切换类型应还原对应状态，**不能串用其他类型的已抽结果**。
- 类型选择器和设置页里的类别名称完全一致，避免用户不知道正在编辑哪个价格表。

### 4.3 轮次与花费摘要

- **轮次不要求用户单独输入**；根据已抽奖品数量 `k` 自动得到「第 `k+1` 抽 / 共 N 抽」。这是为了避免手动轮次与勾选集合发生冲突。
- 示例状态：已抽2件 → 显示「第3抽」「已抽2件」「此前已花费8卡」「下一抽10卡」「抽完本轮累计18卡」「全抽总费用888卡」（以传说武器预设为例）。
- 若还未抽：显示「第1抽」「已抽0件」「此前已花费0卡」。
- 用户改变已抽集合，摘要与结果实时更新；无需再点击「计算」按钮。
- 单轮 / 累计费用使用**当前已保存且生效**的对应转盘价格；费用单位显示「卡」或设置后的「CP」等，不做汇率换算。
- 提供清晰的 **「清空已抽记录」** 操作，只清除当前类型已抽状态，不重置价格或概率配置；误触风险较高时可做轻量确认或支持即时撤销。

### 4.4 奖品卡片网格

- **不制作圆形转盘**，采用规整卡片网格，突出易点选、易辨认。
- 默认名称：**一等奖、二等奖、三等奖……十等奖 / 七等奖**。若用户已在设置中自定义名称，显示名称可以随保存配置更新；等级和稳定 ID 不变。
- 前三等奖拥有特殊标识：
  - 一等奖：皇冠图标（粉紫系）；
  - 二等奖：奖章图标（柔粉色点缀）；
  - 三等奖：星形图标（淡蓝色点缀）。
- 四等奖之后仅用数字 + 等级名称，保持干净一致。
- **未抽状态**：浅色卡片、清晰文字、可点击提示；**已抽状态**：颜色变淡、勾选图标、明确「已抽取」或语义等价标签。
- 点击任意卡片标记为已抽；再次点击取消。用户可以**以任何顺序**选择已抽奖品；顺序不影响计算结果。
- 已抽状态不仅以颜色表达，必须有可读文本/图标；键盘可操作，暴露 `aria-pressed` 或等价无障碍状态。

### 4.5 结果表：概率 + 等效卡片数

展示表头：

| 奖品 | 下一抽中奖概率 | 本轮每100%概率等效卡片数 |
|---|---:|---:|
| 一等奖 | `0.096%` | `10,437.500 卡` |
| 二等奖 | `1.497%` | `668.000 卡` |
| …… | …… | …… |

以上仅为**十抽中已剔除6.5%和10%权重奖品、第3抽需10卡**的示例；真实页面按当前状态更新。

- **默认显示所有未抽奖品**，包括四等奖以后；已抽奖品通过上方卡片状态表现，不必出现在结果表中（也不可冒充仍有中奖概率）。
- 默认按等级从一等奖到末等奖排序；是否增加排序切换不是首版必需，若实现需清楚标示排序依据。
- **中奖概率显示固定3位小数、四舍五入**（例如 `1.497%`）。
- **等效卡片数显示固定3位小数**（例如 `668.000`）；**本轮和累计卡片数显示整数**。
- 计算始终基于内部未舍入数值，**不得用屏幕上显示的概率再次计算成本**。
- `p=0` 时显示「当前不可抽中」；缺价显示「待设置价格」；极小正概率若显示 `0.000%`，需提供「实际大于0，仅因显示精度舍入」说明。
- 结果表底部固定显示：**「等效卡片数仅用于比较本轮性价比，并非实际保底价格或期望总花费。」**
- 可选轻量视觉辅助：数值变化过渡或细薄概率条。概率条不可取代精确数字，极小概率仍应有可见文字。

### 4.6 终局与异常状态

- 只剩**一件且剩余权重大于0**：该奖品显示 `100.000%`；等效成本为该轮单轮价格（保留三位小数）。
- 全部奖品已抽走：页面显示「转盘已全部抽完」，显示最终累计/总成本，**隐藏或置为无下一抽状态**，不可产生第11抽或第8抽（七抽）。
- 若剩余总权重为0：显示清晰错误提示，不把0权重的最后一件强行显示为100%。
- 当前保存配置无效或价格数据缺失：概率与价格分别给出明确错误/占位，不凭空计算数值。细节遵循 `PROBABILITY_SPEC.md`。

## 5. 页面 B：设置中心

### 5.1 整体布局

- 页面标题：**「自定义转盘设置」**；副标题可为「调整每轮抽奖价格与奖品概率」。
- 页面内部设置两个显眼标签页：**「抽奖价格」** / **「初始概率」**。
- 保持统一的白色卡片面板和浅灰底色；**八种转盘行统一视觉**，不按类别赋予不同背景色。
- 顶部或固定操作区始终清楚显示「未保存的修改」状态及**主操作按钮「保存设置」**。
- 价格和概率可以在两个标签之间来回编辑；**同一批草稿须在点击保存后一起生效**，不要切换标签就静默应用。

### 5.2 抽奖价格：8行 × 最多10轮的大表格

PC端必须有完整可编辑总表：

| 转盘类型 | 第1抽 | 第2抽 | 第3抽 | … | 第10抽 | 合计 | 恢复默认 |
|---|---:|---:|---:|---|---:|---:|---|
| 传说载具转盘 | 3 | 5 | 10 | … | 160 | 538 | ↺ |
| 传说近战转盘 | 3 | 5 | 10 | … | 160 | 538 | ↺ |
| 传说载具+武器转盘 | 3 | 5 | 10 | … | 350 | 888 | ↺ |
| 传说武器转盘 | 3 | 5 | 10 | … | 350 | 888 | ↺ |
| 神话武器转盘 | 3 | 5 | 10 | … | 420 | 1008 | ↺ |
| 传说角色转盘 | 3 | 5 | 10 | … | 420 | 1008 | ↺ |
| 神话角色转盘 | 5 | 8 | 15 | … | 550 | 1448 | ↺ |
| 七抽转盘（通用） | 3 | 7 | 18 | … | — | 698 | ↺ |

> 此表是布局示意；**真正的10列完整默认价格不得从上面的省略号推断**，须逐项使用 `PROBABILITY_SPEC.md` §2.3 的八种数组。

- 每个有效轮次为可直接编辑的数值输入框，价格合计由草稿价格**即时求和且只读**；修改总计不表示已保存。
- 七抽第8～10轮显示「—」，不可输入、不可计入合计，不是0元轮次。
- **冻结或保持首列类型名称可见**（横向滚动时尤其重要）；统一表头、统一输入宽度，数值对齐。
- 每行右侧提供「恢复该类型默认价格」按钮，只改变**当前草稿**中的该行；不影响其他转盘。
- 同页提供「恢复全部默认价格/配置」入口；恢复全部前必须确认，操作后仍处于未保存状态，点击「保存设置」后才真正生效。
- 必须支持用户改变价格单位标签（如「使命卡片」与「CP」），但绝不自动换算币种。

### 5.3 初始概率：选择类型 + 奖品卡片网格

- 概率编辑与价格总表**分成不同标签**，避免80个概率输入框一屏堆积。
- 顶部选择8种中的一个转盘类别；每种类别有自己独立的7或10个奖品权重、可编辑名称和单位设置（单位可放公共配置区，避免重复控件）。
- 下方每件奖品用小卡片展示：等级、前三等奖的专属图标、奖品名称输入（或显示名称）、概率数值输入、`%` 单位。
- 十抽显示10张小卡，七抽显示7张；PC端可排成每行约5张，手机端改成两列或一列。
- 卡片布局采用同一风格，前三等奖只做局部图标/柔和强调，不使用大面积金/银/铜色。
- 编辑时实时显示**「概率合计 XX.XXX%」**与是否有效的校验信息；权重的合法性和容差以 `PROBABILITY_SPEC.md` 为准。
- 当合计不合法或有空值/负值时，显示具体错误，**禁用保存**；允许用户继续修改草稿直到合法。
- 「恢复当前类型默认概率」按钮仅改变**当前草稿**中的该类型，不自动提交。
- 十抽七个类型默认概率相同，但**保存后的自定义值相互独立**；修改A类不能悄悄改变B类。

### 5.4 明确保存、取消与离开确认（用户已确认）

这是首版的**硬性要求**，优先级高于 PRD v0.2 中未最终定稿的「保存/应用或自动保存」措辞。

- 输入价格、概率、名称、单位 → 进入**未保存草稿状态**，显示「有未保存的修改」。
- **「保存设置」**：对整份当前编辑草稿执行校验；全部通过后，一次性应用为计算器生效配置并写入浏览器本地存储。显示短暂的「已保存」反馈。
- **「取消修改」**：放弃本次未保存草稿，恢复上次已保存的有效设置；用户已有修改时建议二次确认。
- **「恢复该行/当前类型/全部默认」**：只修改草稿；恢复全部前有明确二次确认；**恢复操作本身不等于保存**。
- 未保存时切换「抽奖价格 / 初始概率」标签，保留草稿，不丢失。
- 未保存时切换转盘类别，也保留各类尚未提交的草稿。
- **未保存时离开设置页**（点击站内导航）：弹出「未保存的修改」确认，允许返回继续编辑或放弃修改；首版可不提供「离开但保留草稿」的第三选项。
- 浏览器刷新/关闭场景可使用浏览器原生离开提醒（受浏览器限制，不能保证自定义提示文案）；不能声称一定拦得住强制关闭。未保存的更改可能丢失。
- 若保存失败（浏览器存储不可用、额度不足等），清晰提示失败，**不要假装已保存**；允许用户保留当前草稿并重试。
- 页面计算区只读取**最后一次保存成功**的配置；设置中尚未保存的数据不可提前参与实际抽奖计算。

### 5.5 手机端价格编辑

- 手机默认进入「选择转盘类型 → 按轮次编辑价格」模式，避免直接塞入过宽的可编辑10列表格。
- 轮次与卡片输入采用纵向或双列网格；显示当前类型累计合计与恢复此类型默认按钮。
- 为满足 PRD 的「8种转盘价格总表可查看」要求，提供**「查看完整价格总表」**入口：可用横向滚动的只读/可编辑表格展示所有8行，首列尽量固定。
- 手机编辑与PC大表格共享同一份草稿；任何布局下都需要明确保存，不可造成两个版本数据不同步。
- 底部主要操作「保存设置」应易于触达，不被虚拟键盘或安全区域遮挡；避免宽表格必须缩放页面才能使用。

## 6. 页面 C：规则说明

### 6.1 页面组织方式

规则说明页采用**单列、居中且限宽**的阅读布局。PC/Mac 与手机保持相同信息顺序，宽屏上不把长段落拉满整个屏幕。

包含四个按顺序排列的模块：

1. **三步使用教程**（短卡片）：选择转盘 → 标记已抽奖品 → 查看下一抽概率、等效卡片数与花费。
2. **概率计算规则**：固定权重、不放回剔除、重新归一化；提供「十抽 / 七抽」示例切换。
3. **性价比说明**：展示 `本轮卡片数 ÷ 当前中奖概率（0～1）`，强调并非实际保底费用或期望总花费。
4. **FAQ 常见问题**：使用折叠面板（Accordion）；每个问题按需展开，默认可展开首项，其余折叠。

顶部保留可见的返回计算器按钮或导航。

### 6.2 三步教程

- 「01 选择转盘」：先确定七抽/十抽及具体类型。
- 「02 标记已抽奖品」：点击卡片选中；再次点击取消。
- 「03 查看计算结果」：系统自动计算下一抽真实概率、等效卡片数与费用。
- 补充淡蓝色提示：**「在设置中可修改初始概率及每轮卡片价格；修改后需要点击保存设置。」**

### 6.3 可切换的七抽 / 十抽例子（首版应实现）

**十抽示例**：前两抽分别获得六等奖（6.5%）和七等奖（10%）；剩余权重 `100 − 6.5 − 10 = 83.5`。第3抽二等奖：

`1.25 / 83.5 × 100% ≈ 1.497%`。

**七抽示例**：先获得七等奖（60%）；剩余权重 `100 − 60 = 40`。第2抽二等奖：

`1.25 / 40 × 100% = 3.125%`。

- 用户可以点击「十抽转盘 / 七抽转盘」切换示例内容；这是**说明演示**，不修改实际计算页面的奖池和已抽记录。
- 用「初始总权重 → 已剔除权重 → 当前剩余权重 → 计算结果」分步展示，尽量减少专业术语。
- 示例中的所有中奖概率显示3位小数；可使用简单的分数或清晰文本表达式，不要求添加重型公式渲染库。

### 6.4 性价比说明模块

- 明确公式：**等效卡片数 = 本轮卡片成本 / 当前中奖概率（小数）**。
- 例子：本轮10卡、目标概率5%，则 `10 / 0.05 = 200.000 卡`。
- 紧邻公式显示提示：**「仅比较当前单次抽奖的概率成本，并非实际保底价格，也不是连续抽到目标的真实期望总花费。」**

### 6.5 FAQ（折叠面板）

至少包含以下问题及答案方向：

| 问题 | 答案要点 |
|---|---|
| 为什么抽走不同奖品，下一抽概率不同？ | 固定初始权重，抽走的权重不同导致归一化分母不同。 |
| 性价比数字是平均抽到奖品的真实费用吗？ | 不是，只代表当前单轮成本除以当前条件概率。 |
| 各奖品显示概率合计为什么偶尔不是100.000%？ | 各项分别四舍五入到3位小数造成显示误差。 |
| 改完概率为什么计算结果没变化？ | 必须在设置页点击「保存设置」，且配置需有效。 |
| 最后一抽一定100%吗？ | 有效且最后剩余奖品权重大于0时是；若剩余总权重为0，则是无效状态，不能强行写100%。 |
| 自定义设置会一直保存吗？ | 仅保存在当前设备/浏览器的本地站点数据；清理网站数据或无痕模式可能丢失。 |

- FAQ 为真实可点击控件；有展开/收起箭头、键盘支持和 `aria-expanded` 或同等可访问语义。
- 不要求复杂展开动画；轻微高度 / 透明度过渡即可。

### 6.6 底部说明和来源

- 显示声明：**「本网站为非官方玩家工具。实际转盘价格、奖品概率和活动规则请以游戏内说明为准。」**
- 可增加「官方规则参考」链接区；在上线前核对公开来源是否可访问并注明适用服务器，不把台服公告称作国服官方公告。
- 页尾不展示与网站无关的广告、无意义注册入口或虚构的官方认证标识。

## 7. 响应式布局标准

| 范围（建议） | 布局行为 |
|---|---|
| 小屏手机：小于640 CSS px | 单列为主；奖品卡片约2–5列，按实际可读宽度决定；状态摘要折行；设置页用逐类表单。 |
| 平板 / 中等屏：640–1023 CSS px | 适度增加卡片列数；可并排部分数据卡；复杂价格表按需要水平滚动。 |
| 桌面：1024 CSS px及以上 | 内容限宽并居中；计算页奖品区与结果区可左右双栏；设置页显示8行完整价格表。 |

- 这些断点是**建议基准**，Codex 可根据实际内容宽度微调；不能为了固定断点牺牲文字可读性。
- 计算页**信息顺序保持一致**：转盘类别/摘要 → 奖品选择 → 完整结果；PC双栏也不得让用户迷失对应关系。
- 不允许移动端出现遮挡核心操作、输入框被裁切、横向页面整体溢出等问题。
- 允许设置页**完整大表格局部滚动**，但移动端的常用编辑应能通过逐类表单完成。
- 使用相对单位、弹性布局、适配安全区域，确保 iPhone Safari 与 Android Chrome 的点击和输入行为正常。

## 8. 动效与反馈

### 8.1 首版可实现的轻动效

- 主按钮 hover / active：轻微明度或阴影变化；点击必须有明确反馈。
- 奖品卡片勾选：颜色 / 边框 / 勾选标识在约150–250 ms内平滑过渡。
- 概率或等效卡片数改变：可使用短暂颜色强调或数字过渡，但**最终准确值必须直接可见**，不可等待动画结束才得到正确数据。
- 设置齿轮旁箭头：微小上下浮动；参见 §2.2。
- FAQ 展开折叠：克制的内容过渡。
- 保存成功：短暂状态提示「设置已保存」，不能在保存未完成前表示成功。

### 8.2 明确不做（首版）

- 圆形旋转抽奖盘、模拟中奖、粒子爆炸、复杂3D武器展示。
- 持续播放声音、自动播放背景音乐、强烈闪屏。
- 随机动画决定实际中奖概率（模拟抽奖是后续独立功能）。

### 8.3 动效可访问性

- 对系统 `prefers-reduced-motion` 用户停用非必要动画。
- 不依赖动画传达唯一状态；「已抽取」「无效」「已保存」必须提供文字或图标。
- 不能把频繁动效放在大面积背景，避免影响阅读和续航。

## 9. 反馈、错误与空状态

| 状态 | 建议表现 |
|---|---|
| 初始未抽取任何奖品 | 显示第1抽、初始概率、已花费0卡；可点击奖品开始标记。 |
| 已抽某奖品 | 卡片变淡 + 「已抽取」图标/文本；结果表移除该奖品，下一抽自动更新。 |
| 清空已抽状态 | 回到该类型初始状态；不清除配置。 |
| 设置被编辑但未保存 | 显示「有未保存的修改」；明确「保存设置」和「取消修改」。 |
| 保存数据非法 | 对具体输入及合计显示错误，阻止保存；旧有效配置继续生效。 |
| 保存成功 | 清楚显示成功提示，计算页读取新配置。 |
| 浏览器存储失败 | 显示失败提示，不伪装成功，不默默丢弃草稿。 |
| 全部奖品已抽完 | 显示「转盘已全部抽完」，不显示下一抽成本或概率。 |
| 剩余权重合计为0 | 显示不可计算状态，附上检查权重的建议。 |
| 当前概率恰好为0 | 显示 `0.000%` 和「当前不可抽中」，不计算除零性价比。 |

## 10. 实现协作与组件建议（非强制）

可考虑将前端拆分为：

- `AppShell` / `TopNav`：网站统一导航及设置提示。
- `DrawTypeSelector`：7/10抽和8种转盘选择。
- `DrawSummary`：当前轮次、已花费、下一抽、累计/保底合计。
- `PrizeGrid` / `PrizeCard`：奖品点击、图标和已抽状态。
- `ProbabilityResults`：所有剩余奖品当前概率与等效成本。
- `SettingsPage` / `PriceMatrix` / `MobilePriceEditor` / `ProbabilityEditor`：统一草稿编辑、校验与保存。
- `RulesPage` / `ExampleSwitcher` / `FaqAccordion`：规则说明与交互示例。
- `ThemeTokens` / `MotionPreferences`：集中管理样式及减少动画偏好。

组件名只是建议，不强制 Codex照搬。关键约束：**UI 不得重写概率数学逻辑；所有计算复用 `PROBABILITY_SPEC.md` 所定义的纯函数结果**。配置编辑使用“已保存数据”和“草稿数据”分离的状态模型。
